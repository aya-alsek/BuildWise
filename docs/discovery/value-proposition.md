# Value Proposition

## 1. Purpose

This document defines the initial value proposition hypothesis for BuildWise.

The purpose is to clarify the value BuildWise aims to provide to its users and the outcomes users may gain from using the platform.

This value proposition is part of the Product Discovery phase and may be refined as further product discovery, user research, and validation are conducted.

## 2. Core User Problem

Software Engineering learners may understand individual concepts and practices but struggle to apply and connect them when building a complete software project.

They may know concepts such as requirements engineering, system analysis, software design, development, and testing, but may still be uncertain about:

* What to do at each stage of a project.
* What should be produced at each stage.
* How one engineering activity connects to another.
* Whether important activities or considerations have been missed.
* Whether their engineering decisions are appropriate for the project.
* How to turn Software Engineering knowledge into practical experience.

This creates a gap between **knowing Software Engineering concepts** and **applying Software Engineering practices in a real project**.

## 3. Core Value Proposition

> **BuildWise helps Software Engineering learners turn their knowledge into practical experience by guiding them through a structured and connected Software Engineering journey while building real software projects.**

The platform aims to connect Software Engineering knowledge with practical project development rather than treating engineering concepts as isolated topics.

## 4. Value Provided

### 4.1 Structured Direction

BuildWise provides a clear project journey that helps users understand:

* What they should work on.
* What comes next.
* What each stage should produce.
* When they can move to the next stage.

This reduces uncertainty when starting or progressing through a software project.

### 4.2 Connected Software Engineering Practices

BuildWise aims to help users understand how different engineering activities and artifacts relate to one another.

For example:

**Requirement → Use Case → Design → Implementation → Test**

The goal is to help users see the project as one connected engineering process rather than a collection of separate documents and activities.

### 4.3 Practical Application

Instead of learning Software Engineering concepts only through courses or theoretical exercises, users can apply those concepts while building a real software project.

This allows Software Engineering knowledge to be practiced within an actual project context.

### 4.4 Engineering Confidence

BuildWise aims to help users make more informed engineering decisions by providing structured guidance, checkpoints, and practical context throughout the project journey.

The goal is not simply to determine whether the software works, but to help users consider whether it was engineered appropriately for its intended purpose.

### 4.5 Practical Experience and Evidence

For learners and recent graduates, completing a structured software project can provide practical experience that complements academic knowledge.

A completed project may include engineering artifacts such as:

* Requirements
* Analysis models
* Design decisions
* Documentation
* Source code
* Tests
* Deployment information

These artifacts can provide evidence of practical Software Engineering experience.

## 5. User Outcomes

Depending on the user's context, BuildWise may help users achieve different outcomes.

### 5.1 Students

Students may use BuildWise to:

* Build graduation projects through a structured engineering process.
* Connect concepts learned across different Software Engineering courses.
* Understand how engineering activities relate to one another.
* Produce organized project artifacts.
* Gain practical Software Engineering experience.

### 5.2 Recent Graduates

Recent graduates may use BuildWise to:

* Build practical software projects independently.
* Gain experience when formal training opportunities are limited.
* Strengthen their Software Engineering skills through practice.
* Build projects and engineering artifacts that demonstrate their capabilities.

### 5.3 Trainees and Independent Learners

Trainees and independent learners may use BuildWise to:

* Practice Software Engineering through real project work.
* Follow a structured project workflow.
* Apply engineering concepts instead of learning them only theoretically.
* Build experience through repeated project practice.

### 5.4 Trainers and Training Organizations

In future versions, BuildWise may help trainers and training organizations:

* Guide learners through a consistent Software Engineering process.
* Monitor project progress.
* Review project artifacts.
* Provide feedback.
* Support practical project-based training.

### 5.5 Universities and Academic Programs

In future versions, BuildWise may help universities and academic programs:

* Provide a structured environment for student projects.
* Support project supervision.
* Monitor project progress.
* Review project artifacts.
* Encourage consistent Software Engineering practices.

These organizational use cases are considered future product directions and are outside the initial individual-user MVP scope.

## 6. Core Value vs. Future Capabilities

The current value proposition focuses on the core problem rather than specific technologies or features.

### Core Value

> **Connecting Software Engineering knowledge with practical project development through a structured and connected engineering journey.**

### Potential Future Capabilities

As BuildWise evolves, the platform may support additional capabilities such as:

* Different project types, including web, mobile, and backend/API projects.
* Technology and architecture guidance.
* Coding assistance.
* Code review and explanation.
* GitHub integration.
* Automated artifact review.
* Requirements and design traceability.
* Testing guidance and validation.
* Team collaboration.
* Mentor and trainer workflows.
* Training organization management.
* University project supervision.

These capabilities are future possibilities and are not considered current MVP requirements.

## 7. Value Proposition Hypothesis

The current hypothesis is that Software Engineering learners need more than access to Software Engineering information or individual development tools.

They may benefit from an environment that connects engineering concepts, project activities, artifacts, and implementation into one practical project journey.

BuildWise therefore aims to provide a structured environment where users can **learn, apply, connect, and demonstrate Software Engineering practices through real project development**.

This hypothesis will be refined as further product discovery and user validation are conducted.
