# User Discovery

## 1. Primary User

The primary user of BuildWise is a **final-year Software Engineering student who is working on a graduation project**.

The user has academic knowledge of Software Engineering concepts and programming, but may struggle to connect this knowledge into a structured process when applying it to a complete software project.

The platform is primarily designed to support the student during the process of planning, analyzing, designing, developing, testing, and delivering a software project.

---

## 2. User Context

The primary user typically reaches the point where they are expected to transform a software idea into a complete project.

At this stage, the student may have already studied topics such as:

* Programming
* Software Development Life Cycle
* Requirements Engineering
* System Analysis
* UML
* Database Design
* Software Design
* Software Testing

However, these topics may have been learned separately across different courses and resources.

When working on a real graduation project, the student must bring these concepts together and apply them as part of one connected engineering process.

---

## 3. User Goal

The primary user's main goal is to:

> **Build and deliver a high-quality software product using appropriate Software Engineering practices.**

This includes more than making the software function correctly.

The student also wants to understand and apply appropriate practices for:

* Requirements
* Analysis
* Design
* Architecture
* Documentation
* Development
* Testing
* Security
* Maintainability
* Other relevant engineering concerns

The student wants to feel confident that the final product is not only working, but has also been developed through a structured and appropriate engineering process.

---

## 4. User Challenges

The primary user may face several challenges while working on a real project.

### 4.1 Knowing Where to Start

The student may have a project idea but be uncertain about how to transform it into a structured Software Engineering process.

### 4.2 Knowing What Comes Next

After completing one activity or phase, the student may be unsure about the next appropriate step or whether the current work is sufficient to move forward.

### 4.3 Connecting Engineering Concepts

The student may understand individual concepts but struggle to understand how they connect throughout the project.

For example:

> Requirements → Analysis → Design → Development → Testing

The student may know each concept separately but not always understand how decisions and artifacts from one stage affect the next.

### 4.4 Validating Engineering Decisions

The student may be able to determine whether the software works, but may be uncertain whether the engineering decisions behind it are appropriate.

For example:

* Are the requirements complete?
* Is the system design appropriate?
* Is the architecture suitable?
* Is the system maintainable?
* Have important security concerns been considered?
* Is the testing sufficient?
* Are the project artifacts consistent?

### 4.5 Managing Project Complexity

As the project grows, requirements, decisions, documents, diagrams, and implementation details can become difficult to organize and keep consistent.

### 4.6 Team Alignment

When working as part of a team, different members may interpret requirements or design decisions differently.

Without a shared and connected project context, this can lead to misunderstandings and inconsistencies.

---

## 5. User Needs

Based on the identified problem and challenges, the primary user may need:

### 5.1 Structured Guidance

A clear path that helps the student understand what to do and what comes next.

### 5.2 Contextual Understanding

The student needs to understand not only **what** to do, but also **why** it is being done and how it contributes to the project.

### 5.3 Connected Project Artifacts

Requirements, analysis, design, documentation, testing, and other project artifacts should be related and traceable rather than existing as disconnected documents.

### 5.4 Practical Examples

The student may need examples and templates that demonstrate how Software Engineering concepts are applied to real projects.

### 5.5 Progress Visibility

The student needs a way to understand what has been completed, what remains, and whether important project activities have been addressed.

### 5.6 Confidence in the Engineering Process

The student needs greater confidence that the project is being developed using appropriate Software Engineering practices rather than simply reaching a working result.

### 5.7 Team Alignment

For team projects, members need a shared understanding of the project, its requirements, decisions, and progress.

---

## 6. User Motivation

The primary user is motivated by the need to successfully complete a software project while developing practical Software Engineering skills.

The student may also want to:

* Produce a higher-quality graduation project.
* Understand how Software Engineering concepts are applied in practice.
* Reduce uncertainty during project development.
* Avoid missing important engineering activities.
* Build confidence in making technical and engineering decisions.
* Gain experience that can be useful when entering the professional software industry.

---

## 7. Secondary and Future Users

The initial focus of BuildWise is the primary user described above.

However, the platform may later expand to support additional user groups.

### 7.1 Recent Software Engineering Graduates

Graduates working on personal projects, portfolio projects, or early professional projects may benefit from a structured engineering workflow.

### 7.2 Software Engineering Trainees

Trainees participating in structured training programs may use BuildWise to practice building complete software projects while following Software Engineering practices.

### 7.3 Training Organizations

Training organizations may eventually use BuildWise to guide groups of students or trainees, monitor project progress, and support mentors or instructors.

### 7.4 Universities and Academic Programs

Universities or Software Engineering programs may potentially use BuildWise as a practical environment for guiding and monitoring student projects.

These future user groups are **outside the initial MVP scope** and are documented as potential future product directions rather than current requirements.
